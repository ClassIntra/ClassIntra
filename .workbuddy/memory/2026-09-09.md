## 模块化改造：插件独立化 / 一切皆可扩展 / 无插件可用（全面模块化 + 删除式自测）

需求：插件独立化，核心不依赖任何插件/可选模块，无插件也能正常构建运行。范围经确认：**全面模块化 + 删除式自测**。

### 审计结论
- 后端本就扫描式解耦（manifest-loader 三源扫描，目录缺失静默跳过）；市场应用热插拔；前端聚合不扫 plugins。
- 违例点：(1) `client/src/views/Browser.vue` 静态 import → `integrations/campusbili-bridge-client.js` 静态 re-export `plugins/campusbili-bridge/*`，删插件即构建失败；(2) server 核心静态 `require('apps/weather/backend/routes')`×3；(3) `/system/app-control` 与 router 的 DB 异常兜底硬编码应用名单。

### 改动文件（已实测）
- 服务端：`server/src/core/manifest-loader.js`（+findManifest/resolveModuleEntry/hasModuleBackend）、新增 `server/src/core/optional-module.js`（存在性加载，缺失→null 降级）；`app.js`/`app-https.js` 天气调度器改为 weather 模块缺失时停用+告警；`routes/admin.js` 手动天气检查缺失返回 404；`routes/system.js` 兜底名单改为按 manifest 推导 + 新增 `GET /api/system/modules`。
- 客户端：`integrations/campusbili-bridge-client.js` 改为 `import.meta.glob` 构建期存在性探测 + noop 降级（Browser 无需改动）；`router/index.js` fallback 由 `loadManifests()` 推导。
- 新增：`scripts/modularity-verify.js`（删除式自测）、`docs/modular-architecture.md`；根 `package.json` 增加 verify:modules* 脚本；DEPLOY.md 增补 5.4。

### 关键技术坑（Windows，脚本内已内置解法）
- junction 作 Vite 根 → rollup 用 realpath 绝对路径 emit index.html 报错 ⇒ client 必须真实拷贝（robocopy /MT）。
- junction 作 server 根 → manifest-loader 由 __dirname 反推生产根，验证失真 ⇒ server 也真实拷贝。
- 模块子项 junction 的 `Dirent.isDirectory()===false`，manifest-loader 按 isDirectory 过滤全跳过 ⇒ 模块源要么整体 junction（apps 完整态），要么真实拷贝必需模块（最小态），plugins/market-apps 直接不挂载。
- better-sqlite3 为 native ABI：启动须用与生产一致 Node（Program Files 24），脚本 `NODE_EXE` 可覆盖；apps 后端 bare import 依赖 `NODE_PATH=server/node_modules`。
- 沙箱/安全删除有 50/次配额：脚本采用“rename 隐藏 + 不删除”零删除策略规避。

`server/src/core/optional-module.js` 三处打磨（均在删除式自测复跑全绿下完成）：
1. **成功才缓存**（上轮已做，防周期任务重复执行模块顶层副作用）；
2. **require 失败不缓存**：瞬时故障（热更半写/语法损坏）下次调用自动重试自愈，无需重启核心；
3. **forceReload/clearCache 同步清理 Node `require.cache`**（关键修复）：此前只清本层 `_cache`，二次 require 命中 Node 旧缓存 → 名义热更实际无效。clearCache 通过 `_loadedEntries` 记录本层加载过的绝对路径统一清理。
