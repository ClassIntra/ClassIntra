# 组网学元管理（xy-mesh）· 部署指南

> 面向自部署者。一个负责人同时管理多个班级的学元发行与小铺交易，不需要任何人工同步——
> 所有操作在管理端完成，配置即时生效，不改代码、不加迁移。

## 一、这是什么

ClassIntra 默认一实例一班：每个班的服务器有自己的学元账本，本班班管管本班的钱。
**组网学元（xy-mesh）**在此基础上提供一种可选的「主班制」：

```
        ┌─────────────── 组网 ───────────────┐
        │                                    │
   ┌────┴────┐                          ┌────┴────┐
   │ 主班 18  │  班管 = 学元总管          │ 从班 08  │
   │ 账本本地 │ ──── HMAC 签名命令 ────→ │ 账本本地 │
   └─────────┘                          └─────────┘
```

- **主班**班管在自家管控中心「学元管理」里，通过一个「班级视角」切换器同时管理
  主班与从班的：线下充值、充值撤回、退款、教师发放/扣减、提现审批、**班级小铺**
  （商品上架/下架、订单履约/结算/退款）。
- **从班**班管的「学元管理」整体隐藏并在服务端封锁（防私自印钱），其余班级管理
  （用户、公告、资源……）完全不受影响。
- **从班学员**无感知：钱包照常用，充值/提现的提示文案自动指向主班班管。
- 钱**始终留在学员所在班的服务器上**——主班只替从班「操作」，不代记账、不同步余额。

适用场景：几个班共用一位负责人收现金/付提现（谁收钱谁管账），或由一位老师统一
管理多个班的班级经济。不适用：希望各班班管财务完全独立的部署——什么都不配即可，
默认行为与历史版本完全一致。

## 二、部署前提

| 前提 | 说明 |
|---|---|
| 两端运行本功能后的版本 | 服务端 + 前端 dist 都要更新（`npm run build` 产物已含全部应用） |
| `RELAY_SECRET` 两端一致 | 组网命令与跨班支付共用这把 HMAC 钥匙；它同时是中继登录所需的配置，正常部署已具备 |
| 网络互通 | 两实例的 9001 端口互相可达（同内网 / Tailscale / 内网穿透均可，填对端**主实例**基址） |
| 时钟同步 | 签名窗口 ±5 分钟，两台机器时钟差需小于 5 分钟（建议都开 NTP） |
| 班号规范 | 学号 `YYCCNN` 中间两位（CC）即班号；组网配置里填**两位**班号 |

## 三、配置步骤（管理端可视化，两班各配一次）

用系统管理员账号（`999999` 或 `BOT_ADMIN_IDS` 内账号）登录：

1. **主班**（管钱的班）：管控中心 → 学元管理 → 底部「组网学元配置」
   - 角色选 **学元主班（统管组网）**
   - 添加从班：填**两位班号** + 从班服务器基址（如 `http://192.168.1.20:9001`）
   - 点「测试」→ 显示「连通，签名校验通过」后「保存配置」
   - 可以添加多个从班（peers 是列表，三个班以上同样支持）
2. **从班**：同样入口
   - 角色选 **学元从班（移交主班）**
   - 填主班**两位班号** + 主班基址 → 测试 → 保存

配置存数据库（`app_config` 表），**即时生效、无需重启**；两端配置顺序任意。
配置完成后：

- 主班班管刷新管控中心，学元管理顶部出现 `本班 / 08班` 视角切换；
- 从班班管的学元管理 tab 自动消失（刷新后生效，服务端同步拦截）。

> ⚠️ 两端都要配。若主班配好而从班没配（角色不是「从班」），主班的所有**写操作**
> （充值/撤回/审批/发放/交易）会显式失败并提示原因——这是防「双头收钱」的刻意设计；
> ping 与各类查询不受限，方便发现漏配。

## 四、配置后的行为变化

| 角色 | 变化 |
|---|---|
| 主班班管 | 学元管理多出班级视角切换；从班视角下可查看学员余额、充值/提现记录、币值健康度，并执行全部财政操作与小铺管理 |
| 从班班管 | 「学元管理」tab 隐藏 + 服务端 403（含直连接口）；其他 tab 照旧 |
| 从班学员 | 钱包照常；「充值」说明与提现成功提示自动改为「找主班 X 班班管」 |
| 从班学员的交易 | 照常在本班小铺买东西；主班班管可在从班视角处理其订单（履约/结算/退款） |

## 五、交易体系（班级小铺 → C2C 市集）

> 自 2026-11 起，小铺从「班管独营」升级为 **C2C 市集**：任何学员都能在钱包
> 「小铺 → 我的小铺」上架商品，同学之间自由买卖，货款直接进卖家本人钱包；
> 班管保留治理权（管理端可下架任何商品、处理任何订单）。账本层天然支持：
> 卖家收款走本人账户，平台毛利只记抽成（fee，默认 0）——同学间交易不会被
> 记成平台利润，不污染经济报表。

主班视角切到从班后，「班级小铺」卡片与本地完全同形：

- **商品**：上架（名称/售价/成本/类型）、下架，直接写入从班商品表（含学员商品）；
- **订单**：查看从班的待处理订单（含同学间的交易单），履约 → 结算；退款
  原路退回买家。资金动作全部落在从班本地账本（`post()` 唯一写入口），
  订单状态机天然防重——已结算的单再结算会被拒。

学员支付/下单/申请退款仍在本班实例完成，与是否组网无关。

## 六、安全模型（部署者应了解的边界）

- **鉴权**：从班只暴露一个 `POST /api/xueyuan/mesh/command`，不吃 JWT，只认
  `HMAC-SHA256(RELAY_SECRET)` 签名 + 时间戳（±5 分钟防重放）。拿到对端命令等价于
  拿到那把密钥，请像保管 `JWT_SECRET` 一样保管 `RELAY_SECRET`，不要走明文信道传输。
- **幂等**：每条命令带唯一 ref，`xy_mesh_log` 落库去重——网络超时后重试不会二次入账。
- **护栏保留**：单笔充值上限、学期配额、镜像账号（永无人登录的影子账号）拒收、
  停用账号拦截等，全部在**从班本地**执行，主班绕不过任何一道。
- **审计**：每条命令（含失败）都记录在 `xy_mesh_log`（ref / 命令 / 状态 / 操作者），
  管理端配置卡内可直接查看最近 20 条。
- **授权回收**：把从班角色改成「不参与组网」或清空配置即可，即时生效；
  主班侧无需改动（写命令会开始失败，从班学元管理随即恢复本班班管可见）。

## 七、故障排查

| 现象 | 原因与处理 |
|---|---|
| 「测试」不通 | 对端地址/端口不对、防火墙、对端 9001 未启动；先在浏览器开 `http://<对端>:9001/api/health` 验证 |
| 「组网签名校验失败」 | 两端 `RELAY_SECRET` 不一致 |
| 「组网命令已过期」 | 两机时钟差超过 5 分钟，配置 NTP |
| 「本班未配置为组网从班…」 | 对端忘了把角色配成「学元从班」，按第三节补配置 |
| 从班班管仍能看到学元管理 | 从班实例未配 member，或前端 dist 未更新（tab 隐藏依赖新版前端） |
| 充值后学员说没到账 | 学元只会在学员**所在班**的实例入账；确认操作视角选对了班，再到该班「最近充值记录」对请求号 |

## 八、给二次开发者

- 命令协议：`POST /api/xueyuan/mesh/command`，头 `X-XY-Mesh-Ts / X-XY-Mesh-Ref / X-XY-Mesh-Sig`，
  签名串 `ts|ref|command|JSON(payload)`，实现见 `server/src/services/xy-mesh.js`
  （`canonical` / `handleCommand`），与 `services/cross-pay.js` 同一套风格。
- 命令集：`ping students overview health recharges withdrawals goods_list orders_list`
  （只读，不要求对端自认 member）与
  `recharge recharge_revoke withdraw_review grant deduct refund goods_create goods_status order_fulfill order_settle order_refund`
  （写命令，要求对端自认 member）。响应形状与本地 `/api/xueyuan/admin/*`、`/api/xy/*` 同构。
- 主班管理代理：`POST /api/xueyuan/admin/mesh/command`（body: `peerClass/command/payload`，
  操作者取登录态）；配置：`GET/POST /api/xueyuan/admin/mesh-config`、连通测试
  `POST /api/xueyuan/admin/mesh-config/test`、审计 `GET /api/xueyuan/admin/mesh/log`。
- 契约测试：`node server/scripts-test-xy-mesh.cjs`（覆盖签名/幂等/封锁/交易/账本不变量；
  需用系统 Node 运行，better-sqlite3 原生模块按其 ABI 编译）。

## 九、本仓库实际部署（8i / 18i）备忘

- 18i（`http://<主班地址>:9001`）= 学元主班；8i（`http://<从班地址>:9001`）= 学元从班；
- 18i 配 peers `[{ class: "08", base: "http://<从班地址>:9001" }]`，
  8i 配 peers `[{ class: "18", base: "http://<主班地址>:9001" }]`；
- 密钥即既有 `RELAY_SECRET`（跨班支付已在用），无需新增配置项。
