# ClassIntra 作为 WebOS：与主流操作系统的多维对标

> 定位声明：ClassIntra 是运行在浏览器里的**班级级 WebOS**——有桌面/窗口化应用模型、
> 应用市场（apps/plugins/themes/widgets 四类模块）、小组件、主题引擎、锁屏、通知中心（超能岛）、
> 全局搜索、设置、内核（BootOrchestrator/ModuleRegistry/LifecycleMachine/ResourceAuditor/
> ResourceGovernor）与设备指令信箱。本文件按操作系统的维度做**诚实**对标：
> 能赢的维度说清楚为什么赢，赢不了的维度不装。每条"领先"都有代码与测试背书。

## 对标矩阵（2026-10）

| 维度 | Windows / macOS / Linux | iOS / Android | ChromeOS | **ClassIntra** | 判定 |
|---|---|---|---|---|---|
| 应用卸载无痕 | 残留注册表/plist/缓存臭名昭著 | 基本干净 | 干净 | **探针验证**：cleanup 钩子 DROP 自建表 + kv 清除 + require.cache 驱逐 + localStorage 前缀清理 + 重装全新状态（`market-lifecycle-probe.mjs` 断言） | **领先** |
| 安装/卸载不重启 | 部分更新仍要求重启 | 应用层不重启 | 不重启 | 热挂载/热摘除（dispatcher 运行时插拔，全班级 WS 同步，秒级生效） | 持平~领先 |
| 第三方资源治理 | 进程资源上限/OOM-killer/cgroup | 同左 + 后台冻结 | 进程模型 | **ResourceGovernor**：用户态资源巡检，未回收计时器/监听器超阈自动挂起（web 平台无人做） | **领先（web 类）** |
| 第三方错误归因 | 崩溃报告按进程归因 | 同左 | 同左 | 挂载期隔离 + 运行期定时器/事件总线错误按应用归因（`[app:名]` / 归属 market:* ） | 领先（web 类） |
| 运行时可观测 | 任务管理器/事件查看器 | 同左 | 同左 | `/dev/runtime` 检查器：每应用实时资源 + 启动耗时 + 订阅归属 + 服务端健康；`window.__ciDiagnostics()` | 达标 |
| 服务自愈 | 服务崩溃自动重启 | 同左 | 同左 | 悬浮层挂载失败指数退避自动重试（3 次）；内核包装器引用计数保证不残留死包装器 | 达标 |
| 权限/能力模型 | UAC/沙箱/权限弹窗，成熟 | 最严格（签名+审核+运行时权限） | Verified Access | capabilities **披露式**（开放模型，装前展示不拦截）——信任边界靠部署者 | 落后（有意取舍） |
| 代码隔离 | 进程级（内核强制） | 同左 + 沙箱 | 同左 | 同进程共享（对标 VS Code Extension Host 而非 Figma QuickJS）；错误/资源/订阅三层治理兜底 | 落后（约束内最优解） |
| 硬件与驱动 | 数十年积累 | 同左 | 依赖 OEM | 无（Web 平台边界） | 不可比 |
| 安全认证 | Common Criteria/FIPS 等 | 同左 | 同左 | 无认证；helmet/CORS/限流/JWT RS256/桥接时序比较等工程实践 | 落后 |
| 更新分发 | 周级滚动 | 商店审核天级 | 同左 | 市场源多级降级 + 版本闸门 + WS 广播全班秒级一致 | **领先（班级域）** |
| 单人可运维 | 不可能 | 不可能 | 需要 OEM | 设计目标即单人运维：SQLite 单文件、pm2、探针脚本回归 | **领先（目标域）** |
| 零遥测 | 争议不断 | 争议不断 | 争议不断 | 诊断全部本地，无任何上报 | **领先** |

## 结论：在哪个战场可以"引领"

ClassIntra 不与通用 OS 比拼硬件/内核/认证——那是数十年工程，且与"班级域 WebOS"的目标域无关。
在**目标域**（单服务器、单管理员、30-60 台 Chrome 80 平板、学期周期）内，以下能力构成
真实的差异化组合，开源世界无现成对标：

1. **卸载即无痕**（有生命周期探针回归的生态承诺）
2. **用户态资源治理**（ResourceGovernor + ResourceAuditor，web 平台独有）
3. **错误按应用归因**（挂载期 + 运行期双层）
4. **秒级全班一致的应用分发**（市场 + WS 广播）
5. **零遥测的全链路可观测**（内核诊断 + 运行时检查器 + 健康快照）

技术决策记录：不采用 Figma 式 QuickJS/WASM 沙箱（Chrome 80 性能代价 + DX 恶化 + 单人维护不可承受），
采用 VS Code Extension Host 式"受控 API + 治理兜底"模型——这是约束内的最优解，记录于此防止反复。

- [ ] 客户端离线韧性 —— **决策：不做**（2026-10，环境实测）。目标环境（X5/Chrome 80 平板 +
      局域网 http 部署）不支持 Service Worker（http 非安全上下文无法注册；X5 内核 SW 支持不可靠），
      离线壳缓存方案在目标域不可达。现有断网保护（offline-secure 锁屏隐藏）已是该环境下的正确形态。
      记录于此防止重复投入。
- [ ] ~~双轨加载器统一~~ **架构决策：不采用**（2026-10 评审）——Vue 2 + Chrome 80 下运行时编译 .vue 无成熟方案
      （无 vue3-sfc-loader 等价物，手写模板编译器体积与安全成本不可接受）；官方应用构建期打包
      与市场应用运行时注入是约束下的正确双轨。"统一"的真实诉求（生命周期/管控/过渡一致）已由
      app_control 管控链、容器变换过渡、卸载无痕覆盖。保留此条作为决策记录，防止后续反复。

系统层仍欠的：能力运行期验证（当前拦截在安装期）、全屏任务切换器与控制中心（表现层，优先级低）。

## 系统层面对标（vs 真实 OS 的机制对照，2026-10）

> 定位共识：对标重心在**系统层**（内核、调度、生命周期、安全模型、分发、可观测性、容错）；
> 前端表现层（手势/动效/视觉）弱一点是可接受的取舍，不作为对标主战场。

| 系统机制 | 真实 OS 的做法 | ClassIntra 对应 | 判定 |
|---|---|---|---|
| 进程模型 | 每应用独立进程 + 内核强制隔离 | 同进程共享（VS Code Extension Host 模型）+ 错误/资源/订阅三层治理兜底 | 约束内最优 |
| 资源治理 | cgroup 限额 / OOM-killer 杀越限进程 | **ResourceGovernor**：审计器实时计数，超阈自动挂起并回收计时器 | **追齐（web 类独有）** |
| 内存泄漏防护 | 内核回收进程地址空间 | 共享劫持引用计数（死包装器零残留）+ detachLifecycle 登记表摘除 + 订阅 owner 整批退订 | **追齐（机制形态不同）** |
| 崩溃自愈 | 服务崩溃自动重启 | 悬浮层挂载失败指数退避自动重试（3 次）；阶段化启动单点故障不阻断 | 追齐（形态不同） |
| 安装/卸载 | 包管理器 + 残留臭名昭著 | **卸载即无痕**：cleanup 钩子 + kv/缓存/require.cache 驱逐 + 重装全新（探针回归） | **领先** |
| 分发完整性 | 驱动签名 / 包签名强制 | **ed25519 目录签名 + 逐文件 sha256**（可选启用，验签失败拒拉取） | 追齐（可选强度） |
| 权限模型 | 运行时权限 + 默认拒绝 | capabilities **披露 + 可选拦截**（`MARKET_RESTRICTED_CAPABILITIES` 配置敏感能力清单，命中拒装） | 部分追齐（开放默认） |
| 更新分发 | 商店审核天级 / 全量 OTA | 市场多源降级 + WS 广播全班秒级一致 + 版本闸门拒降级 | **领先（目标域）** |
| 可观测性 | 事件查看器 / telemetry（争议） | 运行时检查器 + 健康快照 + 请求关联 ID + 慢请求告警，**零上报** | **领先（隐私形态）** |
| 容错关停 | 服务管理器编排 | graceful shutdown：广播→WAL checkpoint→WS/HTTP 关闭→db.close，关停期 503 | 追齐 |
| 一致性回归 | WHQL 认证 / CI 硬件农场 | 六件套 diag + kernel/integrity/lifecycle 三个冒烟探针 | 追齐（规模不同） |

系统层仍欠的：离线韧性（Chrome 80 SW 受限）、双轨加载器统一、能力运行期验证（当前拦截在安装期）。
